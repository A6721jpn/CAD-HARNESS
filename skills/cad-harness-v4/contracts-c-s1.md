# C S1 data and runtime contracts

All new schema tags end in `.v4c` and carry `profile: "c-s1"`. JSON objects are closed to unknown fields; numbers must be finite; booleans are not numbers. Duplicate JSON keys are rejected by the existing ledger parser. All file writes are exclusive. There are no live model/provider calls, hidden acceptance defaults, scripts in plans, or native imports in host admission.

## Schema resources

`design/cad-harness-verify-v4/schemas/` contains `input-manifest.schema.json`, `prepared-inputs.schema.json`, `contour.schema.json`, `capability-plan.schema.json`, `judge-card.schema.json`, `judge-result.schema.json`, `capability-manifest.schema.json`, and precise supporting `step-facts`, `step-recipe`, `contour-recipe`, `contour-source`, and `text-outline` schemas. `capability-policy.json` is the zero-live implementation policy. The standalone plan schema embeds the unchanged build-spec schema; semantic admission still uses the existing `cad_spec.validate_spec`.

## Runtime envelope

The request remains verbatim text. For this profile, `runtime_data.target` is `plan`; stage is `initial`, `parse_repair`, or `repair`. `inputs` is exactly the authenticated model-input projection, including the verified font registry. Optional `selection` is a list of exact `{asset_id, face_id, signature}` entries, with unique, unambiguous original faces. Original-profile keys and observation semantics remain unchanged.

Plan-repair `observations` expose only measured numeric diagnostics, criterion IDs/statuses, numerical uncertainty, safe native error codes and candidate bounds/volume. Checker targets/acceptance thresholds, source paths, masks, recipes and cards are not sent to the generator. Parse repair may see its own invalid response and validation error. A caller cannot replace the authenticated facts or selection with fabricated runtime data.

Completed native geometry failures may consume the single repair slot. Transport/capture failure, missing dependencies, invalid ownership/cleanup evidence or implementation drift stop `INCOMPLETE`; they are not converted to model-repairable geometry failures. Partial streams and the failed work event remain on disk.

Request, input-manifest, prepared-packet and checker-card bytes are pinned before request admission and rechecked before each model/native phase and before accepting a candidate. Changing a card between repair stages invalidates the episode instead of silently replacing its criteria.

## Host APIs

`tools.cad_verify_v4_inputs`:

- `load_manifest(path) -> dict`: validates manifest and every asset, including byte length, SHA256, kind/role, file signature and font-license registry. Paths are relative to manifest parent, canonical slash-separated names. Absolute/drive-relative/ADS paths, traversal, symlinks/junctions/reparse points, special files, and lexical `pilot-user` / `v4-holdout-private` components are rejected before protected filesystem lookup. JSON contour/facts assets must satisfy their exact data schemas. A font has mandatory `glyphs` string and `license_asset_id`; the referenced UTF-8 license is registered with `kind: "license", role: "license"` and a `.txt` or extensionless name.
- `resolve_asset(manifest_path, asset_id, expected_kind=None) -> {record, path, digest}`: `record` is a detached manifest asset record; `path` is an absolute `Path`; `digest` is verified lowercase SHA256. Unknown IDs/missing assets never resolve to defaults.
- `verify_prepared(packet_or_path, manifest_path) -> dict`: strict prepared admission, all original asset digests, manifest digest, STEP before/after provenance, face atlas validity, and contour hash closure. Pure host code; native contour geometry checks are performed separately by the compiler/checker, not falsely claimed here.
- `contour_solid_count(record) -> positive int`: pure host API for authenticated C2 contour records only. Explicit raster `preserve/preserve/preserve` derives source material-component count, checking source/output equality, loop counts and alternating preorder hierarchy; strict raster and independent analytic contours remain exactly one. It admits no plan, context or judge-card count override. Native validation separately certifies spatial nesting and deterministic source regeneration.
- `model_inputs(packet, manifest_path=None) -> dict`: closed allowlist projection, deterministic sorted asset IDs. With a manifest, it re-admits original provenance and exports `fonts: {font_id: {font_sha256, glyphs, license_sha256}}` after verifying font and license bytes. Without one, `fonts` is empty, not invented. Output schema is `cad-harness.model-inputs.v4c`; no paths, recipes, checker masks, license contents, original files, judge cards, or private gold. STEP projection retains source units/axes, bounds, topology, face atlas, and validity/coverage; contour projection retains only geometry/units/topology/nominal width.
- `guarded_path(path, regular=True) -> Path`: lexical-private rejection and no-link/no-reparse confinement; reusable by trusted native consumers.

`tools.cad_verify_v4_plans`:

- `validate_profile(profile) -> "c-s1"`: no implicit selection or aliases.
- `validate_document(value, schema_name) -> dict`: host-only strict schema validation. Names: `inputs`, `prepared`, `step-facts`, `step-recipe`, `contour`, `contour-source`, `contour-recipe`, `text-outline`, `plan`, `judge-card`, `judge-result`, `capability`.
- `validate_plan(value, manifest_path=None, prepared=None) -> dict`: validates family-specific data, existing build-spec semantics, finite nonzero rotation axes, original reference/font IDs/roles and glyph registry when the manifest is supplied, and selected prepared contour when supplied. Engraving supports full axis-angle 3D placement; no silent horizontal-only restriction.
- `validate_judge_card(value) -> dict`: exact metric-specific fields, finite explicit tolerances and criterion IDs. Missing metric acceptance fields or linear tolerance remain missing for `UNVERIFIED`; base schema/profile/source/criteria are mandatory. Present null/nonfinite tolerances are rejected, never defaulted. No user values are inferred from pilot data.

## C1 native API

`inspect_step(manifest_path, asset_id, recipe, out) -> prepared_packet` runs only in a native interpreter with actual FreeCAD/Part. `recipe` is exactly `{schema: "cad-harness.step-recipe.v4c", profile: "c-s1", source_axes: ["X","Y","Z"], source_units: "mm"|"cm"|"m"|"inch", signature_precision_mm: positive}`. STEP length declarations must agree with the explicit source-unit attestation; unsupported/mixed units fail. `Part.Shape.read` imports actual geometry into millimeters. Null/invalid/faceless geometry fails.

The resulting facts contain `source_sha256`, `bounds_mm`, actual topology counts, separate `frame.source_units` and `import_units`, ordered face IDs, area/center/bounds, normals with validity, signature ambiguity, coverage, and input manifest/asset hashes before and after. No bbox-derived thickness: `thickness_mm` is null with a reason. Fingerprints SHA256 the canonical tuple of surface type, area quantized by precision squared, center/bounds quantized by precision, and unit normal rounded to 12 decimals. Identical fingerprints are explicitly ambiguous. Plane normals are constant; other sampled normals carry `local_surface_normal_not_global_face_normal`; unavailable normals are null. Before/after input changes fail, not produce stale successful evidence.

`out` may be a new directory, an already-allocated empty guarded directory, or an exclusive `.json` file. Directory output is `prepared.json`; the packet contains the inspected asset only. The worker/supervisor combines prepared assets explicitly. This helper does not write `result.json` or claim geometric acceptance.

## Contour provenance branches

Raster-derived `cad-harness.contour.v4c` contains exact line/arc loops, source mask row runs, source loops, explicit recipe, registered pixel transform, source/decoded/mask/recipe/record hashes, conservative approximation bounds, topology and processing provenance. Source manifest/image digests bind the original image, not a self-comparison.

The ONE active C2 production recipe is `design/cad-harness-verify-v4/c2-production-recipe-cycle3.json`; `c2-production-registration.json` and `tools.cad_verify_v4_c2_recipe` pin its raw-file and canonical JSON SHA256 and the registration bytes. Earlier production recipes, including `c2-production-recipe-cycle2.json`, remain immutable historical resources, never active fallbacks. Preflight and every C-profile implementation inventory bind active recipe and registration. Explicit `image-to-contour --recipe PATH` consumes it; development recipes are not production substitutes.

Production foreground is `alpha >= 128` regardless of RGB, with no opaque-background requirement. The cycle-three `source_bounded_biarc_v2` branch requires exactly `method`, `maximum_error_mm`, `minimum_iou`, `minimum_radius_mm`, `smoothing_rms_mm`, `sample_spacing_mm`, `biarc_error_mm`, and `maximum_fit_passes`, plus the exact topology object field `connectivity: {foreground:4, background:8, pinch:"remove_locally"}`. Connectivity is required only for v2 and forbidden for every historical/non-v2 recipe. All physical quantities are positive finite millimeters; IoU is positive and at most one; the pass count is an integer from one through eight. `maximum_error_mm` must not exceed `limits.max_deviation_mm`. This branch requires positive `scale.canonical_height_mm`, not `mm_per_pixel`, and prohibits simplification and rounding. Independent recipes may declare other canonical heights; the production recipe pins 50 mm, a source-bound maximum of 1.5 mm, an IoU minimum of 0.90 and a radius minimum of 0.25 mm. There is no mandatory one-pixel ceiling.

Fitting uses source-local coordinates, so transparent padding cannot change its geometry. Exact original source-mask Y extent defines nominal millimeter units before periodic cubic smoothing and shared-tangent equal-distance biarc approximation. A bounded increasing-RMS schedule supplies candidates; then deterministic curvature-constrained periodic B-spline proposals use sampled analytic-Jacobian SLSQP, first preserving branch order alone and only then imposing stronger material-facing width constraints. Sampling and convergence propose geometry, never prove acceptance. Bounded exact parallel line/circle right-normal displacements are additional candidates BEFORE source certification; they may widen material/shrink holes, but never replace source geometry or use polygon buffers as output. Their finite dyadic distances derive from the representation budget and pass count, capped by source error and concave-radius room. Zero displacement remains first. Each candidate independently passes source bounds, exact arc radius/joins, forest, separation and cleared-contact admission; no source-certified or checker-scored output is subsequently offset. The exact-arc shrink reserve excludes unnecessary construction slack. Complete candidates use exact ALL-loop extrema for ONE final uniform scale/translation, registering the unchanged original mask and curves together. Final original-source Hausdorff/IoU, topology and actual geometry remain mandatory. Exhaustion fails closed, never returns an uncertified pixel polyline or increases a gate.

Original inter-loop material walls narrower than the reserved actual-tool diameter prioritize the finer width-constrained proposal before independent RMS choices; void-facing hole–island and separate-piece gaps never trigger this priority. The material proposal starts at the recipe's declared RMS and coarsens only as needed for the unchanged control budget. Other loops retain the branch-order-first path. This is geometry-derived search ordering, not a new gate or case-specific exception; all ordinary alternatives and final independent checks remain.

For retained undersized pieces, source-bounded circle proposals precede the spline proposals. Their fixed finite center search opens original split-contact neighborhoods, retains positive overlap with the original piece, and may grow material only away from that cleared neighborhood. A deterministic cached backtracking search preserves the declared forest and conservative inter-loop gaps; every source loop remains in the returned layout. Original integer mask-origin subtraction precedes nominal scaling so transparent padding cannot change proposal ordering. Source-distance enclosure resolution is independent of the permitted deviation. Complete-layout source-error enclosures use the actual prospective shared canonical scale; a worst-case height reserve protects radius during shrinkage. Arc refinement changes representation accuracy, not a gate. Search/resource exhaustion is a specific refusal, not a proof that compliant geometry cannot exist. Publication and admission still recompute all final certificates against the unchanged mask.

Original-mask IoU certification may halve its polygon-enclosure resolution up to the declared pass count when the initial area tube is inconclusive. The configured flatten tolerance remains an upper measurement bound, and reportable Hausdorff computation is unchanged. Only the certificate is refined: original mask, already-fixed curves, registration and the minimum IoU are never changed. Failure at every bounded resolution remains a refusal.

Material-facing nonlocal branch constraints distinguish material walls/necks from void gaps using the entire original forest. Their separation target uses the actual tool radius with a worst-shrink reserve and fine chord margin, not the larger curvature-construction reserve. Local rejection uses the least possible nominal actual-tool radius; once every root outer is placed, exact root extrema fix the shared final scale, and complete-layout measurement uses `minimum_radius_mm / final_scale`. Early component rejection accounts for possible unplaced-hole deviation envelopes and collars guaranteed by strict separation. Outer–hole and hole–hole walls are material; hole–island and separate-piece gaps are void. Fine polygon disk-opening measurements reject proposals/layouts but never become exported boundaries or independent CAD certificates. Numerical coverage envelopes and measurement buffers never replace the original mask, fitted loops or output. Finite neighbors, frozen normals and sampled curvature can refuse feasible sources; they cannot waive final fidelity, topology, radius or actual tool access.

The source-fit certificate is an internal admission requirement, not either independent fidelity-leg verdict. The fitter consumes only unchanged original mask-cell geometry and explicit recipe quantities: no CAD output, checker verdict, neutral-arm score or post-score repair. Actual output radius >= 0.25 mm, tool access, valid separated native/STEP solids and both independent C-D fidelity legs remain required on every piece. Mask-to-contour IoU >= 0.90 and Hausdorff <= 1.5 mm, and contour-to-CAD IoU >= 0.92 and Hausdorff <= 1 mm, are not relaxed by a successful fit. A small piece may expand within these same original-mask fidelity bounds; source area must never be used as an impossibility test, a component cutoff or permission to drop it. Approximation away from contacts may be inward or outward. No bridge, merge, mask edit, reparative buffer or post-score repair is permitted.

Historical explicit `periodic_cubic_biarc_v1` recipes remain valid with their original closed pixel-space fields and behavior, with no connectivity field and strict diagonal-contact refusal: uniform arclength samples, periodic cubic FITPACK RMS fitting only for loops without detected hard corners, and shared-tangent biarcs certified against the ORIGINAL pixel-cell boundary. Hard-corner loops retain distinct tangents. At most `maximum_fit_passes` attempts halve the declared pixel RMS and select the first source-certified fit; genuine corners may fail actual min-R. Historical validation never redirects to the cycle-three solver or changes archived recipe bytes.

For canonical-height recipes, order is decode/threshold → independently label fg4 foreground and bg8 background → trace exact raw original unit-cell boundary walks and adjacency nesting forest → declared source approximation → exact ALL-piece line/arc extrema → ONE uniform scale to final ALL-piece canonical Y extent → ONE translation to the declared global lower-left. The derived registration maps BOTH original mask and canonical curves; no per-piece normalization, post-scoring normalization or candidate bbox re-registration is permitted. Source geometry and area remain the unchanged original mask-cell union, not repaired polygons. Only declared v2 source walks may touch or self-touch; final loops remain simple, manifold and strictly separated.

Declared production topology is `{components:"preserve", holes:"preserve", islands:"preserve", connectivity:{foreground:4,background:8,pinch:"remove_locally"}}`. Foreground edge adjacency and background edge-or-vertex adjacency independently establish source counts and the nesting forest; fitting never infers the source forest from repaired geometry. Canonical preorder forests have unparented root outers and immediate parent LOOP indices with alternating roles, including material islands inside holes. All material outers count as components and every fg4 component is retained. Topology source/output counts retain exactly `components`, `holes`, and `euler_characteristic`; forest correspondence is checked separately. Strict `{components:1, holes:"preserve", islands:"reject"}` policies remain single-piece (with required connectivity only when v2 is declared); analytic source imports remain unchanged. Empty, infeasible, topology-changing or over-budget inputs fail; disconnected pieces are never bridged/backed/joined/deleted.

Local pinch opening removes material. The original contact vertex must lie strictly outside final MATERIAL with positive conservative clearance, proving a cleared neighborhood rather than only boundary separation or an outward-filled contact. Raster v2 `reports.pinch_openings` is required even when `[]`; each entry has exactly `{vertex_pixels:[x,y], incident_components:[label,...], clearance_mm_lower:value}`. Coordinates are integer original cell vertices in y-up pixel coordinates; incident labels are positive fg4 raster IDs, sorted and unique; clearance is positive finite millimeters in the final frame. Native admission regenerates mask/recipe/hash closure, source adjacency forest, registration, contact inventory and all clearance/source certificates rather than trusting hashes or reported numbers. Missing, extra, reordered-label, fabricated or overstated contact reports fail admission.

C-R8 retains the C-R6 multi-piece cutover: separate solids in ONE native document and ONE STEP compound, with operative whole-output width, origin and thickness edits. Both fidelity legs, actual minimum radius and tool access encompass ALL pieces, including small pieces that aggregate area could hide. Every other family remains exactly one solid. Cycle-three implementation uses generic independent fixtures only; every hash-locked stress case must pass both neutral arms before a custodian U5 run. Declared source pinches do not themselves block v2; uncertified local removal, changed source forest, nonmanifold final output or any other failed case does. No topology or checker threshold is waived. Independent dev proofs authorize no pilot, holdout, benchmark or provider calls.

Fidelity additionally checks a fixed-frame piece/hole correspondence and the nesting forest, not just aggregate component/hole totals. Tool uncovered-area bounds cover the whole output. If `require_connected` is requested for a declared multi-piece C2 output, every material piece must have its own certified connected tool-center region; disconnected physical pieces do not require one cross-piece tool path. Unsupported per-piece connectivity remains UNVERIFIED. Native editability must exercise every output solid collectively; a driving parameter on one piece cannot certify unrelated cached pieces. The compound source graph retains whole-output width/thickness parameters, and invalid edits clear the complete output instead of retaining stale solids.

The neutral worker may lexically admit an exact contour source string once for synchronous recompute/probe/restoration. Only an immutable representation produced by full ordinary contour authentication can suppress repeated source reconstruction; changed `ContourData` bytes always take the ordinary validation path. Every dimension edit still rebuilds actual BREP and is measured/restored, covering all solids. The temporary handle is removed on every scope exit, is never serialized, and does not change the data-only proxy version token or default untrusted construction. There is no global validation cache or input-supplied trust flag. Manifest, prepared/context, implementation/runtime bindings, both format judges and the existing native worker deadline remain enforced.


Independent analytic input uses `cad-harness.contour-source.v4c` with explicit units, bounds, nominal width, exact loops, and `source_image_asset_id`. Its prepared contour branch binds `source_sha256` to that raw registered file, carries `source_image_asset_id` / `source_image_sha256`, exact geometric equality to the raw source, pixel registration, topology, and `provenance: {kind: "independent_analytic_source"}`. It never fabricates raster masks, extraction recipes, preprocessing reports, or source-loop observations. Native contour validation independently checks geometry in either branch.

## Judge card and result

Card source is `independent_dev` or `user`; criteria use explicit IDs and metric kinds `solid_valid`, `bounds`, `volume`, `image_iou`, `boundary_hausdorff`, `min_radius`, `tool_access`, `reference_gap`, `reference_clearance`, `reference_contact`, `translation_clearance`, `reference_play`, `unchanged_dimension`, `engraving`, or `native_roundtrip`. Exact per-metric parameters are in `judge-card.schema.json`. No checker card is generator context.

- Fidelity has two separately registered legs. Min-R and disk-center access remeasure the actual output section, not the prepared contour or a report; section Z is explicit or the declared extrusion's mid-thickness. Min-R uses a numerical interval, not an allowance that silently lowers the radius target.
- Image checking redecodes the bound original image with an explicit channel and foreground/alpha policy. Luminance is integer Rec.601 `(299R+587G+114B+500)//1000`. The checker independently hashes decoded RGBA and canonical row-run masks, requires the committed image/mask and pixel registration, and then measures fidelity. A different mask or convenient registration cannot silently become the baseline.
- `reference_gap` measures a declared parallel planar pair, signed gap/spread and projected overlap. `reference_clearance` checks the minimum distance over complete selected original faces, including curved faces; strict separation uses the lower numerical bound. `reference_contact` bounds the exact selected-face/common-solid contact area, not an invented inflated contact band.
- `translation_clearance` certifies overlap limits only over its declared interval; it is not maximum play. `reference_play` bounds the connected collision-free translation component about the registered datum, with explicit total/positive/negative convention, search interval, positional resolution, volume uncertainty and maximum. Actual interpenetrating samples provide stop barriers; only joined positive-clearance intervals prove a lower reachable bound. Missing stop evidence is UNVERIFIED, never a guessed endpoint. Neither metric proves rotations, friction, compliance or six-DOF fit.
- All acceptance and uncertainty quantities are explicit card data. Missing quantities remain UNVERIFIED. Native roundtrip requires explicit bounds/volume limits and an editable-document requirement.

Result tag is `cad-harness.judgement.v4c`, with `status` and `checks`. Each check has `{id, metric, status, measured, target, tolerance, uncertainty, evidence}`; status is PASS/FAIL/UNVERIFIED. Measurements/evidence are finite data-only JSON, not executable payloads. No missing target or uncertainty is converted to PASS.

## Capability implementation lock

`cad-harness.capability-manifest.v4c` binds code/resources, host and native dependency identities, recipes, optional independent-dev inputs, and the immutable original-profile snapshot. `stage: "implementation"`, `status: "offline_locked"`, `authorization: null`, and `final_v4_ready: false` are mandatory. It does not authorize live work. Original profile resources and observation semantics are intentionally unchanged.

Recipe registry IDs are canonical filename stems (without `.json`), not filenames containing dots. Recipe schema and duplicate IDs are checked before native identity work; only the S1 STEP and contour recipe schemas are admitted.

The implementation lock binds both phase generator identities and the Astra Max judge identity, its same-model-as-pilot caveat, and authoritative user-visual role. Judge and run authorization remain null. C-profile freeze rejects generator/launcher overrides; original-profile freeze rejects C-only asset arguments rather than silently omitting them.
