# C-S3 data-only contract

The plan object contains exactly `schema`, `profile`, `family`, `asset_id`, `source_sha256`, `grid`, `continuity`, `fit_tolerance_mm`, `kernel_tolerance_mm`, `max_degree`, `max_poles`.

- Constants: `schema=cad-harness.plan.v4c`, `profile=c-s3`, `family=surface_rebuild`, `continuity=G2`.
- Bind `asset_id` and SHA-256 to the immutable reference-role original STEP, not a checker asset or a rebuilt candidate.
- `grid` is a nonempty rectangular array: outer index U, inner index V. Each cell contains exactly `face_id`, `signature`, `adjacent_face_ids`, `swap_uv`, `reverse_u`, `reverse_v`. The first three match immutable prepared source identities and complete original adjacency; orientation fields are booleans. Every face appears once; ambiguous or unresolved signatures are denied. Source chart cells are `[i,i+1,j,j+1]` in global `[0,nU,0,nV]`.
- `fit_tolerance_mm` and `kernel_tolerance_mm` are positive explicit numerical work settings, never inferred private user tolerances. `max_degree` is an integer 3–25; `max_poles` is an integer 4–65536 explicit pole resource cap. These are engineering resource limits, not acceptance consensus numbers. Unsupported numerical domains are explicit UNVERIFIED outcomes, not silent approximation.

Construction uses raw finite B-spline/Bezier data or an exact bilinear plane representation, never generic approximate surface conversion. It requires a compatible nonperiodic rectangular tensor chart and preserves its outer boundary before sewing. Rational positive-weight fitting is not itself a metrology certificate. The selected-domain C6 certificate currently supports nonrational nonperiodic rectangular B-spline/Bezier faces, with hard limits of degree 12 and 4096 poles/spans per face. Selected planes, rational/periodic surfaces, nonrectangular trims, ambiguous registration, singularity and exhausted resources remain UNVERIFIED where no supported certificate exists; never exclude a scored case or relax its card to conceal that result.

Prepared input, facts and recipe documents must each explicitly carry c-s3. S3 faces add a measured `parameterization` object: `domain_uv=[u0,u1,v0,v1]` with strictly ordered finite domains; `corner_points_mm` in 00,10,01,11 order in the source global frame; `degree_u`, `degree_v` integers for spline surfaces or both null with `reason=non_spline_surface`; otherwise reason is null. These are source measurements, not gold or a rectangular trim certificate. S2 precision, signature and adjacency invariants still apply.

Native editability is an actual interior `PoleOffsets` (`App::PropertyVectorList`) on `SurfaceRebuildProxy`, restored data-only and applied during recomputation. Boundary poles are immutable. The generated operative feature history is new; it does not recover original STEP source history. Native verification must exercise recomputation and independent reopen rather than accepting cached shape or alleged fit error.

Independent cards select candidate regions by measured geometric bounds and registered full parameter/chart maps, not trusted output face numbers. G1 and G2 include complete positional seam coverage; G2 additionally requires invariant oriented shape-operator agreement in a physical tangent frame, not raw derivative equality. All targets, units and numerical resource settings are explicit card fields. Certification yields PASS only from a global upper bound within acceptance, FAIL from a valid lower witness above acceptance, otherwise UNVERIFIED. Never use sample maxima as certificates or send private targets through repair feedback.

An output patch card `domain_uv` is either explicit numeric `[u0,u1,v0,v1]` or the explicit selector `native_full`. The latter requests the independently measured full native `Face.ParameterRange`, including STEP endpoint roundoff; it does not permit cropping, clipping or widening acceptance. Judges record resolved domains, cover actual native knot seams and require unchanged global-complement identity even for faces crossing the registered region bounds.

A complete native c-s3 handover must include `solid_valid`, `face_count`, `surface_deviation`, `g2_continuity` and `native_roundtrip` criteria. G2 includes positional/G1 conditions; a separate G1 criterion is also available. Focused cards remain valid for individual measurements but cannot certify the full generation pipeline. All unselected source faces and all unmapped candidate faces require bijective continuous support/trim preservation evidence; equal face count, a successful fitter or a clean rendering is insufficient.

CLI `--profile c-s3` selects this pipeline for preflight, prepare-step, merge-prepared, prepared-bundle, compile/verify, replayed request/run and offline implementation freeze. Original and C-S1/C-S2 defaults are unchanged. Freeze binds all implementation/skill/schema/policy/native environment/dev generator bytes plus original and prior stage archives; authorization remains null and final_v4_ready false. No G3, no live capability, no source-history recovery claim.
