# 議題：Harness² に「Diluted Persistence（薄い永続化）」を足す案は妥当か（CAD などドメイン特化ハーネス向け）

## 論文 Harness²（Web検索で確認）
- Xu ほか（Google Cloud AI Research）"Harness^2: Recursive Agent Harnessing for an Open World", arXiv:2610.14224（2026-10-09）https://arxiv.org/abs/2610.14224 、コード https://github.com/google-research/harness2
- 仕組み（論文要旨とリポジトリの記述から）：
  - タスクレベル再帰：現在のタスクの実行ハーネスを Propose–Probe–Compose で改善する。編集案を出し、同じタスクで同条件で効果を試し、実行間の挙動の対比に支えられた変更だけを合成する。正解の検証器は使わない。並列再帰（k 候補）と逐次再帰（k 段）がある。
  - ハーネシングレベル再帰：採用したハーネスと「証拠に支えられた教訓」をドメイン別ライブラリ（継続的な改善ハーネス）に保存する。前の実行ハーネスは引き継がず、再利用できる部品と「いつ・なぜ効いたか」の教訓を選んで残し、次のタスクの提案と合成を導く。同一ドメイン内のタスクは順に実行し、それより前のエントリだけを読む。
  - 結果：1ステップで GLM-5 と Gemini 3.5 Flash が基準ハーネスより改善（WorkBuddy-Bench 最大 +11.5、JobBench +4.5、LAB 部分合格率 +11.8pt）。
- つまり、実行ハーネスは毎回ベースから始まり、経験はライブラリに残る。

## 提案（Diluted Persistence）
- 実行ハーネスは今まで通り毎回ベースから始め、経験はライブラリに残す。
- ただし CAD のようにタスク分布が安定したドメインでは、直近 N タスクのうち一定割合以上で有用と判定された改善を、ベースハーネスへ「薄く」永続化する。上書きではなく、衝突しない追加か、低い優先度での合流にする。悪化したらロールバックする。
- 交絡のある改善（他の変更と同時に入って効果が切り分けられないもの）は優先度を下げる。
- 例：形状検証の手順、失敗からの回復スキル、CAD カーネルとの安全なやり取り。
