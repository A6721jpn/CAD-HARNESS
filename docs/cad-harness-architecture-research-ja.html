FreeCAD / SOLIDWORKS専用LLMハーネス：設計意図・拘束・ネイティブ履歴を保持する構成

調査日：2026年10月17日｜第一候補：DeepSeek Harness／代替：Pi｜設計提案・実装前｜要約改訂版

推奨：DeepSeek Harness＋独立したCAD基盤

アーキテクチャ更新：LLM向けの設計操作と観測を中心にした再設計案・図解を追加。以下は先行手法と設計要件の調査資料です。

DeepSeek Harness（DSH）を第一候補とし、型付き設計グラフ、各CADのネイティブ変換器、観測器、編集テストをCordisプラグインで接続する。LLMは変更案を作り、CADは実行結果を画像・履歴・拘束・実測値として返す。検証を通った版を採用する。

成果物は主要寸法を直接編集できる.FCStd／.SLDPRT。初期形状が合うだけでなく、寸法変更後も指定した関係を保ち、ハーネスを停止してもCAD単独で使えることを合格条件にする。

1. 「完璧な履歴」を、編集できる仕様として定義する

一枚の絵から裏側・実寸・肉厚・元の作成順は一意に決まらない。目標は絵と確認済み仕様に整合し、予定した編集を正しく伝播させる履歴である。曖昧さは仮定として残し、重要なものだけ質問する。

形状

寸法、穴数・深さ、貫通、断面、向き、body数を実測する。

編集性

駆動寸法・拘束・式が実在し、変更後も関係を保つ。Fixの乱用は不可。

持続性

意味の分かる履歴を保存・再生成でき、人間の変更を次の編集へ引き継ぐ。

完全拘束でも駆動寸法は変更できる。自由度ゼロと、設計意図を持つ編集可能性は別の評価項目。

2. 既存手法から採るもの、補うもの

機能は一次資料で確認。課題欄は「両CADで人間が編集する」という本提案の要件に照らした評価。

3. 全体構成：型付き変更と、実際のCAD観測を往復する

提案初期構成は主エージェント一つ＋決定的なCADツール群。設計グラフ・変換器・検証器をDSHから分離し、モデル推論とCAD実行も別プロセスにする。

図は本提案。画像・履歴・実測を同一revisionから返し、必要な局所情報だけ追加取得する。CADの待ち時間や障害を会話・保存処理へ波及させない。

4. 画像入力：解釈と、その根拠を一緒に渡す

平面輪郭・三面図・立体ポンチ絵・写真を区別する。楕円が円の投影である場合や寸法補助線もあるため、ベクトル化は候補生成に使い、直接押出用スケッチへ確定しない。

入力パケット保持する内容・使い方
原画像＋局所crop元解像度・向き・元画像上の領域・view ID・hash。補正前画像も保存し、全景と細部を実際のimage contentとして渡す。
寸法・記号OCR候補、φ/R/深さ、単位、対象、領域、確度。「6か8か」「径か半径か」は未確定のまま比較する。
形状・意図部品、軸、対称性、押出/回転、視点、隠れ領域の候補。主要寸法、独立/従属変数、編集後に保持する関係を記録する。
根拠・不明点observed / user_confirmed / inferred / assumedと画像領域・判断理由・競合。仮定を確認済み仕様に見せない。

明示指示・確認済み仕様→明瞭な寸法注記→幾何的証拠→慣習を基本順とし、確認済み情報同士の矛盾は確認する。パース画像のピクセル長を実寸とみなさない。質問は貫通/止まり、寸法基準、端余白/ピッチの保持など、結果への影響が大きいものに絞る。

VLM・OCR・線円検出は候補を作り、CADソルバーと実測が拘束を検証する。単位・縮尺不明のモデルは暫定扱いにする。[4][8]

5. 設計グラフ：形状と「変え方」を保存する

層保存するもの
意図・仕様要求、独立/従属パラメータ、不変条件、有効範囲、根拠、未解決事項。
製作定義基準、スケッチ、プリミティブ、拘束、輪郭、フィーチャー依存DAGと作成順。
ネイティブ対応文書・configuration、意味ID↔feature/寸法/参照の対応、実行状態。
実行記録親revision、patch、API結果、観測、検証、snapshot hash、backend版。CADのフィーチャー履歴とは区別。

寸法は値＋単位、式は許可演算子のASTにする。次元不一致・未定義値・範囲違反・循環依存を実行前に拒否し、任意コード式を評価しない。mm/deg↔APIのm/rad等はアダプターで変換する。[28]

非循環なのはフィーチャー依存と明示的な寸法式。幾何拘束は閉路を含めて同時に解く。向き・符号・配置領域も保持し、別解や鏡像への反転を検出する。

二つ穴の板：同じ初期形状でも、編集の答えは異なる

共通初期値はL=100、W=40、T=8、D=6、端から穴中心までe=15 mm。P=L−2e=70、穴中心はx=±P/2、y=0。Lを140へ変えたとき、eとPのどちらを保つかが設計意図になる。

ネイティブ履歴：XY基準→中心矩形スケッチ→厚さTの押出→XY上の二つ穴スケッチ→+Z貫通カット。矩形の水平・垂直・一致・中心・寸法、穴の同径・対称・径・位置を独立な拘束に展開する。初期座標はソルバーの初期値とし、寸法と拘束で駆動する。

輪郭の閉鎖性、穴/外周、座標系、方向、対象bodyを明記し、過拘束を避ける。繰返しにはパターン、回転対称には回転を選び、フィレットは通常後段へ。履歴の短さより主要寸法の分かりやすさを優先する。

6. LLM ⇄ CADの入出力契約

通常経路はset_parameter / add_constrained_sketch / add_feature / change_extent / replace_referenceなどの型付きpatch。一つのフィーチャーに必要な幾何と拘束をまとめ、CAD側で検査する。

公開ツール案役割・主な戻り値
capabilitiesbackend・version、feature/constraint別の作成・読取・編集・変換・検証能力、単位・制限。
observe / inspect指定revisionの概要・差分・view。必要時に局所グラフ、隣接、断面、測定方法付き実測。
resolve_reference意味条件から対象候補を検索。候補ID、支持条件、一意性、注釈画像。
evaluate_patch候補文書で実行・再構築・テスト。candidate/job ID、delta、検証結果。
commit_candidate基準版を再確認して合格候補を採用。新revision、保存文書、監査記録。
job_status / cancel長時間処理の状態取得・取消し要求。
reconcile_native / export人間編集の差分・競合を取込。検証済みnative、派生STEP、検証manifestを出力。

書込みにはdocument_id / configuration_id / base_revision / request_idを必須にする。版の比較で先行変更の上書きを防ぎ、request IDで重複実行を防ぐ。自由コードの試作は候補workerに限定し、型付き操作の未対応を隠さない。

STEPは検査・交換用、meshは表示用。履歴移植は各CADの専用変換器で行い、インポート形状を元の駆動寸法・拘束の代替にしない。[31]

8. 面・辺は、意味と幾何条件で選ぶ

Face3/Edge7や固定座標の最近傍だけでは、寸法変更や辺分割で別対象を拾う。生成面への依存を減らし、基準面＋オフセット式→作成由来・意味→native参照→幾何条件→学習による候補を組み合わせる。FreeCADの緩和機構やSWのpersistent referenceも、消滅した対象の意味を保証しない。[21][23]

例：「板上側の外周辺」＝作成元base_pad、z=T、終端面と外側面に隣接、穴由来を除外、期待数4。分割後の集合を許す条件と、複数候補なら返す方針も持つ。ロール名は提案上の定義で、APIが直接返す名前ではない。

曲線種・方向・局所座標・数・単位付き許容差で候補を再検証する。曖昧なら注釈画像を返し、自動で付け替えない。indexや表示名は対応表に閉じ込め、複製先では文書ID・参照・対応を再取得する。HistCADの固定点参照の弱点を減らし、FutureCADは候補検索へ使うが、任意のトポロジー変更を保証するものではない。[10][11]

9. 候補文書で試し、人間の編集を引き継ぐ

文書・IR・対応表・検証を一つのrevisionで管理する。基準状態には未保存変更、configuration、外部参照、編集中スケッチを含め、ファイルhashだけに頼らない。Undoやネイティブtransactionを、両CAD共通の完全なロールバックと仮定しない。

1文書1書込主体とし、並列候補は別文書・別プロセスへ。合格候補の採用は保存文書・manifest・対応表を復旧可能な段階状態で切り替える。CADと保存先をまたぐ分散ACIDは仮定しない。

queued → running → validated → committedとfailed / cancelled / outcome_unknownを区別する。COM中の取消し要求は完了とは限らない。タイムアウト後はrequest IDと実状態を照合し、無条件に再実行しない。再起動対象は破棄可能なworkerに限り、利用者のCADを停止しない。選択セット、active文書、モーダルダイアログも監視する。[16]

人間編集の取り込み範囲

初期版は公開パラメータの値変更を正式対応とし、式の従属値は上書きしない。名前・対応済みfeature/拘束の追加削除は段階的に取り込み、契約との差異を提示する。未対応featureや外部参照はnative内で保持し、opaque境界として周辺編集・他CADへの移植を制限する。

変更イベントでdirtyを付け、安定した再構築時に差分抽出し、書込み直前にも再照合する。意味IDは文書内＋sidecarに保存し、紛失時は回復できる範囲だけ復元する。古いIRから全再生成せず、元版を残して派生モデルを作る。

10. 品質評価：形状・編集・履歴を別々に測る

寸法・拘束などの必須条件を先に満たし、その後に見た目や履歴の分かりやすさを比較する。画像類似度やLLMの自己評価で必須条件の失敗を相殺しない。

検査合格条件
仕様・幾何寸法、穴数・深さ、貫通、肉厚、body数、solid妥当性を生成形状から実測。コンパイラと別の測定経路を持ち、既知モデルで観測器も検証。
拘束・履歴駆動寸法・依存関係が存在し、失敗・欠落・予期しない抑制がない。Fix乱用を検出。意図した未拘束は明示。
寸法変更目標値へ到達し、指定関係と未変更寸法を保って全履歴が再構築。全変数の一括拡大だけで済ませない。
永続性・往復保存・閉じる・再読込・再構築、人間編集→次のLLM編集が成功。ハーネス停止中も主要寸法を変更可能。
見た目・両CAD投影・断面を補助評価し、手描きの歪みを考慮。両backendで同じ仕様と編集契約を公差内で満たす。

有効範囲も納品する。板ならT>0、e>D/2、W>D、P=L−2e>Dなど。基準値、独立変数ごとの増減、境界付近、相互作用、失敗例の回帰を試す。穴が外周へ開く・pattern数が変わる等は構造変更として別検証する。有限サンプルは連続範囲全体の保証ではなく、形状成立は強度・加工性の保証でもない。

絶対長さ・相対形状・角度の公差を用途とサイズに応じて固定し、実測・検証条件を保存する。画像やファイルのbit一致は要求しない。

最初の比較実験

板・フランジ・回転部品・ブラケット等の約30部品に、人間作成の仕様・基準モデル・手描き/寸法図/曖昧図・複数編集要求を用意する。これは初期規模案で、統計的十分性を主張する数ではない。

  • 比較：直接API生成／MCP反復／IR＋観測／IR＋観測＋編集テスト。モデル・入力・予算を共通化。
  • 品質：初期仕様・編集全条件の合格率、native編集可能寸法率、保存再読込、人間編集保持率、黙った誤参照率。
  • 運用：質問数、手直し時間、LLM回数、再構築時間、費用、復旧率。寸法違いや近い部品family・作者が調整側と評価側に漏れないよう分割。

HistCADの評価観点を参考にし、その成功率と独自集合を直接比較しない。提案の改善効果は比較実験で判断する。[10]

11. DeepSeek Harnessを第一候補にする

優先順位は利用者の製品方針を反映し、CAD精度の実測順位ではない。初期実装はDSHへ集中し、Piは代替候補として残す。

CAD基盤の責務

intent-schema、patch-planner、reference-resolver、validation、revision-store。状態はSQLite等、成果物はimmutable保存。両CAD workerと観測・描画・context要約を分離する。

接続・表示の責務

DSH pluginを先行し、Pi/MCP接続は必要時に追加。UIは原画像・解釈候補・主要寸法・履歴・仮定・差分・検証・派生版を表示する。

境界はversion付きJSON-RPC/ローカルIPC等。接続主体を確認し、任意コード実行を既定でネットワーク公開しない。MCPを採用しても排他・保存はCAD基盤が管理する。会話ログはCADの唯一の保存先にせず、各ターンで最新仕様・能力・未解決事項をストアから再投入し、会話分岐とCAD派生版をIDで結ぶ。

12. 実装順：両CADと人間編集を、小さい部品で通す

段階実装と、次へ進む条件
P0：API実証LLMなしで二つ穴の板を両CADに構築。寸法・式・拘束・履歴を読取。保存再読込、人間の寸法変更、失敗時の原文書保全を確認。
P1：CAD基盤小さいIR、型検査、両コンパイラ、能力表、revision、candidate、観測器とDSHツール接続。誤単位・参照不一致・競合を拒否できること。
P2：画像生成DSH上で画像領域・寸法読取・意図・仮定・基本feature・観測ループを統合。部品群の仕様と編集契約に合格し、曖昧な入力で確認できること。
P3：修正・派生意味参照、局所修正、フィレット/面取り、パターン、対応済みfeatureの人間編集。既存寸法・履歴を保持し、不要な再作成を避けること。
P4：拡張・学習部品familyを拡張し、成功・失敗修正・人間修正を蓄積。必要なら学習。family分離評価で改善を確認。Pi追加時も同じ適合試験に通す。

初期範囲は単品機械部品、平面スケッチ、直線・円・円弧、基本拘束・基準面、押出、貫通/止まりカット、回転、単純パターン。自由曲面・複雑な板金・溶接構造・アセンブリは後段とする。

最初の到達点は、二つ穴の板を「絵→ネイティブ履歴→人間の寸法変更→LLMの派生編集」まで通す実証。FreeCADだけで作り込む前に、両CADで入出力・参照・同期の前提を確かめる。
