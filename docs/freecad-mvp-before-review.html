1. 合格した能力を積み上げる、10段階のMVP

各段階は前段までの回帰試験を維持する。未解決の参照・保存・拘束問題を残したまま、部品数だけを増やさない。

段階・完成するもの新しく実装する能力次へ進む合格条件
M0｜接続とAPI実証DSH・FreeCADの版固定、JSON往復、画像返却、ライブ状態のコピー。将来のリスク確認として、標準Assemblyで2部品・固定ジョイントも試作する。GUI内実行・未保存状態の複製・保存再読込を確認。Assemblyの作成／参照／solve／診断を実機で確認し、未解決点を台帳化。

M4｜複雑な単品溝・ポケット、回転体、穴列、ミラー、リブ、面取り・フィレット。操作ごとに対応範囲と編集テストを追加。L字ブラケット、段付き軸、フランジ、リブ付きハウジング、取付板の5系統で履歴追加と派生を実演。各系統10件の寸法変更と不正変更を検証。

M7｜10〜20部品・部分組立外部ファイル、再利用リンク、部品定義と配置の分離、サブアセンブリ、全体寸法の共有、依存ファイル一式の版管理。20部品・2階層の治具で、共通部品の全体更新と1個だけの派生を実演。別フォルダでも参照が解決し、人間の子部品編集も保持。
M8｜50部品・可動構造影響範囲の再計算、変更部分の観測、干渉検査、可動域の姿勢試験、専用CADプロセスと中断復旧。50部品のスライド治具で寸法・部品交換・移動を反復。閉ループ機構は別の四節リンクfixtureで確認してから対応表へ追加。
M9｜100部品の継続編集
目標リリース		混成・再利用中心・異種部品中心の負荷試験、長い編集履歴、故障注入、配布・復元・性能計測。最終合格表を全て通す。100部品で生成・人間編集・LLM派生・再読込を繰り返せる対応範囲を明記して出荷。

「100部品」は末端の実配置数。ボルト・ナット・ワッシャーも数え、配列は展開数で数える。サブアセンブリの箱は二重計上しない。「固有の部品定義数」も別に記録し、1種類を100個配置するだけでは最終合格にしない。

M4内の順番：①ポケット・溝 → ②回転体 → ③穴列・ミラー → ④リブ → ⑤面取り・フィレット。各操作を一つずつreleaseし、画像からの仕様抽出も5系統へ拡張する。仕上げ処理は基本形状と取り付け基準が確定してから追加する。

3. 最小構成でも、LLM向けの設計操作を境界にする

接続：DSHの既存Web profileにTypeScriptプラグインを追加し、JSONのジョブフォルダを介してFreeCAD内のPythonブリッジへ渡す。要求は一時名で書き、同一ボリューム内のrename後に受け付ける。QTimerで読み、CAD操作はGUIスレッドで直列実行。文書IDを明示し、ActiveDocumentに依存しない。

役割：LLMは設計案と変更範囲を決める。CADサービスは意味IDを寸法・拘束・featureへ変換し、結果を実測して採否を判定する。会話履歴をモデルの正本にしない。DSHのloopは公開プラグイン拡張点で接続する。[1]

最初はJSON manifest＋FCStdで十分。M8では重い候補計算を専用FreeCADプロセスへ移すが、LLMに見せる契約は維持する。GUI・Python/Qt・保存APIの互換性をM0で実測する。

エラーはcode / target / violated_condition / observed / allowed_actionsで返す。例：「右穴が端面に接触」「jointの参照先が消失」「子部品が基準版から変化」。M6以降は配置数、未接続部品、joint残差、干渉ペアも返し、全B-Repや100個分の履歴は毎回渡さない。

6. 板は、FreeCADに自然な履歴として残す

文書の中身

Document
├─ Params（Spreadsheet：主要寸法）
└─ Body（PartDesign::Body）
   ├─ Origin
   ├─ BaseSketch（拘束付き矩形）
   ├─ BasePad（厚さT）
   ├─ HoleSketch（同径・対称な2円）
   └─ HolesCut（貫通Pocket）

完成Shape一個に置き換えない。意味IDと人間向け表示名を分離する。

拘束と駆動寸法

矩形は一致・水平垂直・原点対称とL/W。穴は中心同士の原点対称・同径・径D・左中心y=0・左中心x=−P/2。全要素Fixを使わず、独立した拘束で完全拘束する。[4]

Spreadsheet aliasを名前付き拘束とPadへ式で接続。PはLとeの従属値。[5]

両SketchはXY基準、Padは+ZへT、Pocketはz=0から+Zへ貫通する構成を試験する。方向・Through allのenumは採用版で確認し、Face番号の変化に依存しない。[6]

5寸法のaliasはplate_length / plate_width / plate_thickness / hole_diameter / edge_offset、従属値はhole_pitch。値は単位付きで保持し、表示名は日本語でも、意味ID・native名との対応は変えない。

形状の合格：solid=1、外形L×W×T、実在する円筒面と開口から2つの貫通穴・径・中心を確認。体積は独立式(L×W−2π(D/2)²)×Tとも照合する。式の値を読むだけで実測済みにしない。

初期試験範囲：L80〜180、W30〜80、T4〜16、D4〜12、e12〜25 mm。その範囲内でもe>D/2、W>D、L−2e>Dが必要。比較の初期許容差は長さ10−4 mm、体積相対10−6を候補として実機で較正する。これは加工公差ではない。

標準Assemblyへ変換する

FreeCAD 1.1.3の公式ソースではAssembly::AssemblyObjectとAssembly::JointGroupの作成を確認できる。部品はApp::Link、部分組立はAssembly::AssemblyLinkを使う経路がある。これを初期候補とし、Assembly3/4などを混在させない。[8][11]

jointは標準Assemblyの実装を使う。意味上のportを、nativeの参照と局所配置へ結び付ける。人間が寸法を変えた時も、FreeCAD単独で接続が追従することをM5〜M6の条件にする。固定座標を保存しただけの配置では合格にしない。標準jointが使うFeaturePythonは許容し、独自ハーネス専用の形状生成オブジェクトへの依存は避ける。[9]

solveの成功だけでは、意図した拘束が十分かまでは分からない。固定忘れ・冗長・過拘束などの戻り値を解釈し、接続残差と想定自由度を別に調べる。全体の自由度を取得するAPIは未実証なので、取得できなければunknownとし、固定jointの接続解析・既知機構の解析・摂動試験を組み合わせて検証する。[10]

「100部品でも壊れにくい」ための設計ルール

  1. 取り付け基準を安定させる：原点・datum・式で定義したportを優先。生成面を使う場合はfeatureの由来と幾何条件で一意性を検査する。トポロジー対策があっても、参照の意味が変わっていないか確認する。[13]
  2. 寸法の依存は一方向：共有Spec → 部品寸法 → port → 配置・joint。M7では独立した共有仕様FCStdの寸法をnativeの式で参照する方式を検証し、JSONだけで関係を保持しない。兄弟部品が相互に寸法を決める構成は禁止。SubShapeBinderも版を固定した検証済み参照を一方向に接続する。[14]
  3. 3種類の構造を混同しない：履歴・寸法依存は循環禁止、組立の親子関係も循環禁止。一方、jointの接続には四節リンクのような閉ループがあり得るため、機構として別の合格試験を置く。
  4. 共有と派生を明示：App::Linkで共通部品を再利用し、定義更新の影響先を列挙する。「この1個だけ」は定義を分岐して配置を置換。可変の作業ファイルを共有ライブラリの正本にしない。[12]
  5. 自由度は設計どおりに残す：接続された組立の基準部品を固定し、すべてをgroundして帳尻を合わせない。剛体組立は0、ヒンジやスライダは予定した1自由度。追加の浮遊・回転を検出する。

絵からの組立はM7で導入：まず分解図・ポンチ絵から部品一覧、共有寸法、接続候補を作り、各部品をM3〜M5の経路で生成する。部品数・裏側・締結方式が不明なら確認事項にする。一枚の絵から100部品分の非可視構造を確定した扱いにはしない。

8. 人間編集の取り込みと、壊れない派生保存

  1. 編集終了を確認：セル入力・Sketch編集が未確定ならEDIT_IN_PROGRESS。自動操作を開始せず、確定済みのライブ状態を読む。
  2. 対応範囲を照合：M2は5寸法・ラベル変更、M5から対応済みfeature、M7から対応済み配置・jointへ拡大。式の解除・未知featureなどは差分を示す。人間の変更を消して再生成しない。
  3. 最新状態を版にする：未保存変更もsnapshot化。元文書の保存先・dirty状態を保つ保存方法をM0で確認する。意味上のfingerprintで版を判定し、ファイルhashは破損検査に用いる。[7]
  4. 候補を隔離：最新snapshotの履歴を複製し、指定箇所だけ変更。M7以降は変更部品・依存する親組立・参照先の版をmanifestで固定し、候補のリンク先を付け替える。元の可変ファイルへ参照を残さない。
  5. 依存一式で検証：子部品の未保存編集も含め、読取の前後とcommit前に全基準版を照合。全件が一貫していなければSTALE_BASEで再取得する。初期は自動の三者マージを行わない。
  6. 検証済みの版を公開：一時領域へFCStd・manifest・画像・検査結果を書き、全体を再読込してから公開記録を確定。応答はその後に返す。別フォルダへ一式を移し、元フォルダに頼らず参照が解決することも試験する。

複数ファイルを一つの保存操作で原子的に更新できるとは仮定しない。不変の部品版、段階的な書出し、最後の公開manifest、再開時のhash照合で回復可能にする。編集用作業文書と不変snapshotは分ける。

jobはqueued → running → validated → committed、またはfailed / cancelled / outcome_unknown。同じIDに違うpayloadを渡したら拒否する。取消し要求と取消し完了を区別し、重いrecomputeの即時停止は保証しない。M8の専用プロセスが停止しても、人間の作業中FreeCADは終了させない。

9. 「破綻なく」を、再現可能な合格条件にする

採用されたモデルは、形状・履歴・接続・保存の検査に合格していること。失敗・未判定の変更は採用せず、原本と復旧可能な状態を残すこと。これを全段階の不変条件とする。LLMの完遂率と、不正なモデルを採用しない整合性は別々に測る。

検査軸M9の合格条件（これから実施する試験）
形状・履歴全生成部品のB-Repが有効、意図したsolid数、recomputeエラーなし。主要寸法・拘束・feature履歴が保存され、定義した範囲で変更できる。
参照・組立全リンク先・port・jointが一意に解決。寸法変更後も接続残差が許容内。剛体・機構ごとの自由度条件を検証でき、不明なものを0と扱わない。
干渉・可動域AABBで候補対を絞り、B-Repの距離・交差体積で確認。面接触と体積干渉を区別。圧入等の例外はペア・理由・版付きで記録。1自由度の可動域は端点を含む25姿勢と既知の危険姿勢で試験。
人間との継続編集各100部品モデルで100回の混合編集（人間40／LLM60）、途中で10回の保存・終了・再読込。共有寸法、1個の派生、部品交換、joint変更を含み、意図しない巻戻し・原本破損0件。
LLMの完遂率事前固定した適合依頼を3モデル各30件、最大2回の候補修正で評価。合計95%以上の完遂を目標とし、失敗理由・要求回数も記録。不正採用0件は別の必須条件。
障害・復旧外部参照欠損、曖昧port、子部品の同時変更、joint過拘束、solver失敗、タイムアウト、重複要求、保存途中停止、返答消失を注入。黙って代替形状を確定せず、前の正常版へ戻れる。
引渡し別フォルダから全ファイルを再読込し、DSHなしで主要寸法・native jointを編集。版・共有関係・未対応操作・検証範囲がREADMEとmanifestから分かる。

25姿勢の検査は連続した全運動の無干渉証明ではない。サンプリングで不足する接触機構や狭い隙間は追加の適応検査を要求する。幾何許容差・jointの位置／角度許容差・意図的接触はモデルごとに明示し、単一の万能閾値にしない。

100部品の試験モデルを3種類用意する

A｜再利用中心

100配置／20定義。フレーム・プレート・締結部品。共通定義の更新が必要な全配置へ伝わるかを試す。

B｜実用的な混成

100配置／60定義。3階層の治具・スライド機構。寸法共有、外部参照、部品交換、可動域を試す。

C｜異種部品中心

100配置／100定義。板・軸・ブラケット・ハウジングの混合。形状再計算と履歴・観測の負荷を試す。

各モデルのfeature数・面数・joint数・閉ループ数・階層深さ・画像解像度を固定して記録する。部品数だけで性能を保証しない。閉ループの合格はまず小さな既知機構で取得し、100個の可動部品に一般化しない。

性能は、20部品の時点で測り始める

同じPCでcold/warm各10回、形状生成・solve・干渉・保存・画像・LLM待ちを分けて計測し、中央値・p95・最大メモリを残す。暫定目標は100部品で概要inspect p95≤2秒、単品寸法変更の評価≤30秒、全体検証≤120秒（LLM応答時間を除く）。M7の実測後に機材とモデル条件を添えて確定する。

対策の順序は、①部品版ごとの形状cache、②変わった依存範囲だけを再計算、③干渉の候補対の絞り込み、④LLMへ概要＋必要箇所だけ返却。commit前は依存一式の整合性を検査する。時間超過を合格扱いにせず、job継続または候補不採用として返す。
