目標リリース		混成・再利用中心・異種部品中心の負荷試験、長い編集履歴、故障注入、配布・復元・性能計測。最終合格表を全て通す。100部品で生成・人間編集・LLM派生・再読込を繰り返せる対応範囲を明記して出荷。

3. 最小構成でも、LLM向けの設計操作を境界にする

接続：DSHプラグイン→requests/→独立したPython調整役→FreeCAD。調整役だけがjob状態・最終manifestを書く。GUIとworkerは割当て先にsnapshot・候補を書くだけ。GUI内のQTimerで状態を取得し、重い再計算・検証・画像は別workerで行う。文書IDを明示する。

役割：LLMは設計案と変更範囲を決める。CADサービスは意味IDを寸法・拘束・featureへ変換し、結果を実測して採否を判定する。会話履歴をモデルの正本にしない。DSHのloopは公開プラグイン拡張点で接続する。[1]

最初はJSON manifest＋FCStd、同時に候補1件。workerはM2から分離し、GUI凍結・視点変更・計算停止が原本へ波及するのを防ぐ。headlessで標準Assemblyや画像出力が動くかはM0で確認し、必要なら専用GUI workerを使う。renameは期限付きで再試行し、公開記録を読み戻してから応答する。

4. LLMが指定する操作と、CADから返す情報

提案API共通ツールは初期から固定し、利用可能な設計操作を増やす。以下は新規実装する仕様であり、FreeCAD標準APIの名称ではない。

共通ツール契約

cad.inspectライブ文書と依存文書を読み、revision・意味ID・人間変更を返す。読取中に式を修復しない。M6以降は部品／port／jointを絞り込める。
cad.evaluatebase_revisionとopsを受け、候補内で実行。原本への直接反映は行わず、検証と差分を返す。
cad.commitcandidate_id・候補hash・必須検証を照合して別派生へ採用。同じ派生意図・候補の再commitは、request_idが変わっても同じ採用結果を返す。

CADが返す観測の仕様

識別：revision、candidate_id、意味ID、native object対応表。

状態：L140/W40/T10/D8/e15、Pの式、独立・従属変数、変更前後。

実測：外形140×40×10、貫通穴2個、径8、中心±55、solid数。要求値とは別欄に格納。

検証：拘束状態、履歴エラー、保持条件、再読込、編集試験ごとのpass/fail/unknownと根拠。

視覚：同じrevisionの上面図・等角図。画像失敗はpreview状態として返し、形状検証とは分ける。M2の画像返却試験は別に必須。M6以降は変更・接続部を絞る。

上記は期待結果。今回CADを実行して得た数値ではない。

エラーはcode / target / violated_condition / observed / allowed_actionsで返す。例：「右穴が端面に接触」「jointの参照先が消失」「子部品が基準版から変化」。M6以降は配置数、未接続部品、joint残差、干渉ペアも返し、全B-Repや100個分の履歴は毎回渡さない。

派生の基準：base_policy="require_current"を既定とし、最終照合でライブ版が変わっていれば拒否する。特定snapshotからの派生を明示した場合だけ"snapshot"を使い、base_divergedと基準値を表示して別枝へ保存する。作業対象は自動で切り替えない。

DSHでは型付きJSONを正規の結果にし、output.renderでテキストと画像へ変換する。exec.signalを取消し要求へ伝える。プラグインはtool callとrequest_idを対応させ、再送は同じIDで行う。未完了・結果不明の間は同じ文書の新規変更を待たせ、同じ内容なら既存jobを照会。payload hashはIDの不正再利用を検知する。ユーザー依頼から派生意図variant_intentをプラグインが発行し、再evaluateにも引き継ぐ。採用は意図ごとに1件。同じ候補の再commitや採用済み内容の再evaluateは既存結果／duplicate_ofを返す。別枝には新しい意図が必要で、LLMの再試行だけでは発行しない。[2]

6. 板は、FreeCADに自然な履歴として残す

文書の中身

Document
├─ Params（Spreadsheet：主要寸法）
└─ Body（PartDesign::Body）
   ├─ Origin
   ├─ MountLeft / MountRight（式駆動LCS）
   ├─ BaseSketch（拘束付き矩形）
   ├─ BasePad（厚さT）
   ├─ HoleSketch（同径・対称な2円）
   └─ HolesCut（貫通Pocket）

完成Shape一個に置き換えない。意味IDと表示名を分離する。LCSはM0で確かめたnative型を使い、初期から組立用の基準を残す。

拘束と駆動寸法

矩形は一致・水平垂直・原点対称とL/W。穴は中心同士の原点対称・同径・径D・左中心y=0・左中心x=−P/2。全要素Fixを使わず、独立した拘束で完全拘束する。[4]

Spreadsheet aliasを名前付き拘束とPadへ式で接続。PはLとeの従属値。[5]

両SketchはXY基準、Padは+ZへT、Pocketはz=0から+Zへ貫通する構成を試験する。方向・Through allのenumは採用版で確認し、Face番号の変化に依存しない。[6]

5寸法のaliasはplate_length / plate_width / plate_thickness / hole_diameter / edge_offset、従属値はhole_pitch。値は単位付きで保持し、表示名は日本語でも、意味ID・native名との対応は変えない。

形状の合格：入力寸法を測定値として流用せず、B-Repからsolid=1、外形、2穴の径・中心・両端の開口と貫通を確認。二つ穴の板は独立式(L×W−2π(D/2)²)×Tとも照合。M4では加工の重なり・分割面に対応し、局所断面と追加／削除体積を併用する。

初期試験範囲：L80〜180、W30〜80、T4〜16、D4〜12、e12〜25 mm。その範囲内でもe>D/2、W>D、L−2e>Dが必要。比較の初期許容差は長さ10−4 mm、体積相対10−6を候補として実機で較正する。これは加工公差ではない。

7. アセンブリでは「部品定義・配置・接続」を分ける

データ保持する内容防ぐ失敗
PartDefinitionasset_id、revision、FCStd、寸法・履歴、公開port。形状cacheは版ごと。共有部品を変えたつもりがなくても全コピーが変わる。
Occurrenceoccurrence_id、親階層、定義版、配置姿勢。配列も末端を識別。「右の1個」の変更が別の配置へ作用する。

Joint両端の配置＋port、種類、offset、可動域、残差、対応するnative joint。見た目だけ合っていて、寸法変更で離れる。
AssemblyRevision依存する部品版一覧、外部参照、共有仕様、BOM、検証、親版、hash。親だけ保存され、子部品が古い版や未保存状態になる。

標準Assemblyへ変換する

FreeCAD 1.1.3の公式ソースではAssembly::AssemblyObjectとAssembly::JointGroupの作成を確認できる。部品はApp::Link、部分組立はAssembly::AssemblyLinkを使う経路がある。これを初期候補とし、Assembly3/4などを混在させない。[8][11]

標準jointへportを結び、人間の寸法変更後もFreeCAD単独で接続が追従することを条件にする。ソースには参照から局所配置を更新する経路があるが、実機成功は未確認。M0で穴LCS→Link→joint→L変更→新規プロセスでの再読込まで試す。標準jointのFeaturePythonは許容し、独自の形状生成クラスには依存させない。[9]

無効参照から原点・無回転の配置へ戻る経路もあるため、座標一致だけでは合格にしない。参照の存在・型・対象の意味を検査し、非ゼロ位置・回転のdatumと参照切れを対にして試す。[15]

solveの成功だけでは、意図した拘束が十分かまでは分からない。固定忘れ・冗長・過拘束などの戻り値を解釈し、接続残差と想定自由度を別に調べる。自由度APIが未取得ならraw値はunknown。有効な3軸LCSを6自由度拘束することが実証されたfixed jointの連結木だけ、ground 1個・全配置への接続・残差で0自由度を検証する。冗長な閉路は追加fixtureとsolverの扱いを実証するまで未対応。一般機構を摂動だけで証明しない。[10]

「100部品でも壊れにくい」ための設計ルール

  1. 取り付け基準を安定させる：原点・datum・式で定義したportを優先。生成面を使う場合はfeatureの由来と幾何条件で一意性を検査する。トポロジー対策があっても、参照の意味が変わっていないか確認する。[13]
  2. 寸法の依存は一方向：共有Spec → 部品寸法 → port → 配置・joint。M7では独立した共有仕様FCStdの寸法をnativeの式で参照する方式を検証し、JSONだけで関係を保持しない。兄弟部品が相互に寸法を決める構成は禁止。SubShapeBinderも版を固定した検証済み参照を一方向に接続する。[14]
  3. 3種類の構造を混同しない：履歴・寸法依存は循環禁止、組立の親子関係も循環禁止。一方、jointの接続には四節リンクのような閉ループがあり得るため、機構として別の合格試験を置く。
  4. 共有と派生を明示：App::Linkで共通部品を再利用し、定義更新の影響先を列挙する。「この1個だけ」は定義を分岐し、共有寸法の継承／凍結を明示。分岐後の共有寸法変更も試験する。ライブラリ新版の作成と組立への採用を分け、接続条件を破る組立候補は公開しない。[12]
  5. 自由度は設計どおりに残す：接続された組立の基準部品を固定し、すべてをgroundして帳尻を合わせない。剛体組立は0、ヒンジやスライダは予定した1自由度。追加の浮遊・回転を検出する。

絵からの組立はM7で導入：まず分解図・ポンチ絵から部品一覧、共有寸法、接続候補を作り、各部品をM3〜M5の経路で生成する。部品数・裏側・締結方式が不明なら確認事項にする。一枚の絵から100部品分の非可視構造を確定した扱いにはしない。

8. 人間編集の取り込みと、壊れない派生保存

  1. 編集終了を確認：未確定入力はEDIT_IN_PROGRESS。検出不能ならFreeCADの「入力を確定してAIへ渡す」操作と基準値の確認でsnapshotを確定し、未確認の100を140の代わりに使わない。この経路もM0で実証する。GUI不在はLIVE_UNAVAILABLE。rawセル内容・式・拘束値・構造を版にし、計算値と分ける。
  2. 対応範囲を照合：M2はParamsの5寸法とラベル、駆動式の維持が条件。式切れ・未知featureは変更を保持して対応可能な操作を返す。基準自体の再計算が失敗すればBASE_INVALIDで止める。M5から明示的なadopt_feature / repair_relationを候補差分として扱い、inspect中に修復しない。
  3. 未保存状態を複製：原本の保存先・dirty・形状を変えない方法をM0で確認。取得前後の入力版を照合する。workerは複製を無変更で強制再計算し、取得した値・式を保つことを確認してから基準形状を測る。古いB-Repを差分の基準にしない。[7]
  4. 候補だけを変更：履歴を複製し、指定箇所だけpatch。M6でbundle形式を決め、M7で依存一式を版固定。未保存文書を複製し、既存の不変snapshotはhash照合で再利用する。式・Linkの参照先をbundle内に閉じ、意味IDを文書／定義／版で解決する。
  5. 保存と再読込を検証：候補を保存・終了し、新規workerで開いて再計算・計測・画像化。元の作業文書は閉じない。M7は別フォルダへ複製し、元の参照先が利用できなくても復元できるか試す。M7では個別派生・再利用する1定義＝1 FCStdを原則とし、文書版＋object IDで対応を記録する。複数定義を同居させる最適化は後回し。
  6. 最新の基準版へ照合して公開：採用済みの派生意図・候補なら既存結果を返す。新規採用は子部品を含むsnapshot・候補hash・必須検証を照合。require_currentの基準時点は最終ライブ照合時で、不一致はSTALE_BASE。ファイルを先に保存し、intentを主キー・candidate_idを含む公開manifestを一つだけ確定する。

複数ファイルの一括更新が原子的とは仮定しない。入力のfingerprintは版判定、ファイルhashは保存物の照合に使う。不変snapshotと作業文書を分け、途中停止時は公開manifestとhashから採用済みかを回復する。

最小jobはqueued → running → validated → committedと失敗・取消し。結果不明なら既存jobを照会する。取消しと公開を直列化し、取消し済みの候補は公開不可、公開が先ならcommittedを返す。GUI照会の失敗でも検証済み候補は保持し、snapshot方針へ自動変更しない。workerの強制終了でも人間のFreeCADは終了させない。分散DBや自動マージは初期MVPに入れない。

9. 「破綻なく」を、再現可能な合格条件にする

採用されたモデルは、形状・履歴・接続・保存の検査に合格していること。失敗・未判定の変更は採用せず、原本と復旧可能な状態を残すこと。これを全段階の不変条件とする。LLMの完遂率と、不正なモデルを採用しない整合性は別々に測る。

検査軸M9の合格条件（これから実施する試験）
形状・履歴全生成部品のB-Repが有効、意図したsolid数、recomputeエラーなし。主要寸法・拘束・feature履歴が保存され、定義した範囲で変更できる。
参照・組立全リンク先・port・jointが一意に解決。寸法変更後も接続残差が許容内。剛体・機構ごとの自由度条件を検証でき、APIのraw自由度がunknownでも、認定済みの別検証がpassすればよい。検証方法自体がunknownなら採用しない。
干渉・可動域AABBで候補対を絞り、B-Repの距離・交差体積で確認。面接触と体積干渉を区別。圧入等の例外はペア・理由・版付きで記録。1自由度は端点を含む25姿勢＋危険姿勢を前の解から連続追跡。姿勢の枝飛び・特異点付近は刻みを細分化し、追えなければunknown。
人間との継続編集各100部品モデルで100回の混合編集（人間40／LLM60）、途中で10回の保存・終了・再読込。共有寸法、1個の派生、部品交換、joint変更を含み、意図しない巻戻し・原本破損0件。
LLMの完遂率開発用と分けた未見の適合依頼を、下記3つのCAD試験モデル各30件で固定。初回と最大2回修正後の成功率を別報告し、後者95%以上を目標とする。範囲外依頼の拒否率・不正採用0件は別評価。
障害・復旧外部参照欠損、曖昧port、子部品の同時変更、joint過拘束、solver失敗、タイムアウト、重複要求、保存途中停止、返答消失を注入。黙って代替形状を確定せず、前の正常版へ戻れる。
引渡し別フォルダから全ファイルを再読込し、DSHなしで主要寸法・native jointを編集。版・共有関係・未対応操作・検証範囲がREADMEとmanifestから分かる。

合格率・不正採用0件は試験集合での成績であり、任意の形状への保証ではない。25姿勢は連続した全運動の無干渉証明ではない。サンプリングで不足する接触機構や狭い隙間は追加の適応検査を要求する。幾何許容差・jointの位置／角度許容差・意図的接触はモデルごとに明示し、単一の万能閾値にしない。

100部品の試験モデルを3種類用意する

A｜再利用中心

100配置／20定義。フレーム・プレート・締結部品。共通定義の更新が必要な全配置へ伝わるかを試す。

B｜実用的な混成

100配置／60定義。3階層の治具・スライド機構。寸法共有、外部参照、部品交換、可動域を試す。

C｜異種部品中心

100配置／100定義。板・軸・ブラケット・ハウジングの混合。形状再計算と履歴・観測の負荷を試す。

各モデルのfeature数・面数・joint数・閉ループ数・階層深さ・画像解像度を固定して記録する。部品数だけで性能を保証しない。閉ループの合格はまず小さな既知機構で取得し、100個の可動部品に一般化しない。

性能は、20部品の時点で測り始める

snapshot取得中のGUI停止時間も独立に測り、100文書でも常に短いとは仮定しない。worker構成を固定し、同じPCでcold 10回の中央値・範囲、warm 30回以上の中央値・参考p95・最大メモリを記録。生成・solve・干渉・保存・画像・LLM待ちを分ける。暫定目標は100部品で概要inspect p95≤2秒、単品寸法変更の評価≤30秒、全体検証≤120秒（LLM応答時間を除く）。M7の実測後に機材とモデル条件を添えて確定する。

対策の順序は、①部品版ごとの形状cache、②変わった依存範囲だけを再計算、③干渉の候補対の絞り込み、④LLMへ概要＋必要箇所だけ返却。commit前は依存一式の整合性を検査する。時間超過を合格扱いにせず、job継続または候補不採用として返す。

確認済み／これから確認すること

初回調査ではこのPCのNodeとdshを検出し、packageは@deepseek-ai/dsh 0.2.1-rc.1。起動・モデル接続・拡張APIの互換性は未検証。FreeCADはPATHとProgram Files直下の限定探索で見つからず、未インストールとは断定していない。

FreeCAD 1.1.3を固定候補とする。公開リリースと同タグのAssemblyソースは確認済みだが、Python呼出し・datumからjointへの接続・保存復元はM0で実証する。ソースの更新経路を実機成功と扱わない。DSHも専用profileで版を固定し、既存global導入を無条件に更新しない。[3]

モデルはDSH上で画像入力とtool callingが通るものを一つ固定し評価する。今回の成果物は計画書であり、CAD生成、FreeCADの導入、100部品の実性能試験は未実施。
