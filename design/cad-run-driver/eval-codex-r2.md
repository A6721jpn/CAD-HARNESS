# E2 / codex：grok評価への批評と合意案

案1はgo with changes、案3はno-goに同意。今回のA試作は案1だけとし、案2・案4の実装を同時に始めない。

## 相違点ごとの立場

- 【譲歩｜案2】現状の採用・対照実験は保留にする。ただしrun1通過は「一度の初期設定が成功した」証明ではなく、run2停止だけで恒久的no-goとは断定できない。設定持続は未確認として将来の検証候補に残す。
- 【譲歩｜案4】Aの初回試作では調査仲介を作らない。複雑課題では、driverが許可したAPI資料と自分の結果だけを読む別条件を検討できる余地を残す。
- 【残る対立｜案4の理由】読取調査が必ずfixture/evidence参照やシェル再導入になる、という一般化には同意しない。driver仲介で両方を禁じられる。ただし実装コストと効果は未確認。
- 【訂正｜失う能力】runbookが禁じるのはfixture・既存reports/evidence等であり、API資料や自分の結果の調査まで全部禁止してはいない。案1で失う能力が「もともと禁止した範囲だけ」とは言えない。
- 【同意｜exec/resume】grokの変更案も当面は独立execなので実質合意。修正ごとに共通仕様・前回ソース・結果を再送し、run間で引き継がない。resumeの設定維持・同一使用量系列は未確認で、途中で方式を切り替えない。
- 【同意｜生usage】turn.completedのinput_tokens、cached_input_tokens、cache_write_input_tokens、output_tokens、reasoning_output_tokensを出典付きで残す。累積性・包含関係は未確認で、引き算や全フィールドの足し算はしない。
- 【補足｜driver記録】run/呼出し/attempt/sessionの対応、CLI版・model/effort・設定、AGENTS識別、prompt/sourceハッシュ、開始終了・終了状態、最終out-dir/exit/result参照を残す。重複usageを加算せず、失敗時の未取得はnull。
- 【残る対立｜壁時計】Sol rolloutだけの壁時計では、driverが行うCAD・保存・結果処理が範囲外になる。driver開始から最終結果までを主時計とし、exec/cad_run呼出し時間は内訳として分離する。
- 【譲歩｜API断片・例】初回Aは仕様・build契約・実行環境だけで開始し、APIコード例を追加しない。将来追加するなら版と内容を固定し、対照条件にも同じ情報を渡す。fixture・寸法入りの正解例は渡さない。
- 【同意＋補足｜修正情報】grokの列挙項目に、実際のexitと取得済みerror_type等を加える。診断値はデータとして扱い、秘密・個人パスを除く。存在しない例外文・実測値は補わない。
- 【同意＋補足｜修正上限】初回＋修正最大2回。next_actor=solに加え、文書close・所有プロセス終了を確認する。cleanup_pending、human、JSON不正、未知の担当先は停止。型式不正等を理由に隠れた追加呼出しをしない。
- 【残る対立｜例外診断】現在のJSONは例外種別だけで原因行等が不足し、stderrにも詳細が必ず残るとは言えない。A先行は可だが、複雑課題の前にサニタイズした例外文・発生行を返す別変更を評価する。調査だけで補えると断定しない。
- 【同意｜過去比較】過去・条件B・driverを別条件とし、既存aggregateを保存する。7秒のPINGやexec_command不使用を時短の証拠にしない。環境停止・CAD未到達も残し、geometry未取得はnull。
- 【留保｜公平性】同一セッションに複数スナップショットがあるだけでは公平性は成立しない。モデル・入力情報・キャッシュ・試行上限・測定範囲も揃える。全usageと初回を除くsession_deltaを直接比較しない。
- 【留保｜結論の強さ】N=5完了も単独では因果の証明にならない。過去データは参考比較、揃えた再実験で方式差を評価する。速度・トークンの改善幅は［推定］または未計測として、削減率・費用を断定しない。
- 【同意｜安全境界】Solのシェルを外してもworkerが生成Pythonを実行する信頼境界は残る。cad_runの合否・所有回収・human経路・J1無効を維持し、bypassへ自動切替しない。

## EVAL-CONSENSUSへ入れる変更点リスト案

- 対象は案1のA試作。案3はno-go、案2・案4は今回保留として、将来の再評価条件を記す。
- BRIEFの確認済みexec設定で独立呼出しを採用し、resume・全ツール無効化の実効性・長い生成の挙動は未確認事項に残す。
- Sol返答はbuild(doc)を定義する完全なUTF-8ソース。初回情報を固定し、fixture/evidence/他run解答を渡さない。
- driverが入力検査・新規出力先・cad_run起動・結果検証を担当し、初回＋最大2回修正、Sol担当かつ安全な終了確認時だけ続行する。
- 生usageと呼出し識別・設定・ハッシュ・終了状態を記録し、重複排除・未取得null・累積性確認前の集計禁止を明記する。
- 主時計はdriverの全工程。Sol rolloutとCAD sidecarを分け、measure_rollout.pyを変えず、session_deltaのゼロを使用量ゼロとしない。
- 例外診断不足を既知の制約に記し、複雑課題前の構造化診断追加は別変更・別検証とする。今回cad_runの判定を変更しない。
- 過去との参考比較と条件を揃えた再実験を区別し、初期設定費、warm-up、停止run、追加情報の差を隠さない。

根拠：eval-grok.md、eval-codex.md、および両評価が参照するBRIEF・runbook・cad_run実装。今回は批評のみで、コマンド・CAD・外部APIを実行していない。
